| 새로 만든 파일 | 원본 | 무엇이 바뀌었나 |

| `README.20260803.md` | — | 이 문서 |

### ⚠️ 배포할 때 꼭 기억할 것

GitHub Pages는 **`index.html` 이라는 이름의 파일만** 화면으로 보여줍니다.
`index.20260803.v1.html` 을 그대로 올리면 **앱은 하나도 바뀌지 않습니다.**
그래서 올리기 직전에 **이름을 바꿔서 덮어쓰는 한 단계**가 필요합니다. (아래 6·7번에 명령어가 있습니다)

```
index.20260803.v1.html   →  index.html    로 복사해서 올림
sw.20260803.v1.js        →  sw.js         로 복사해서 올림
gas/Code.20260803.v1.gs  →  gas/Code.gs   로 복사해서 올림 (+ GAS 편집기에도 붙여넣기)
```

버전 파일(`*.20260803.v1.*`)은 **되돌릴 때 쓰는 보관본**입니다. 같이 올려두면 나중에

## 2. 오늘 반영한 내용

### ① 📎 첨부파일 기능 (요청 1)

**어디에 생겼나** — 제목칸과 본문칸 **사이** 입니다.

```
┌──────────────────────────────────────┐
│ [개인용]  [집안용]  [회사용]           │
│ [ 2026-08-03 ] [ 14:32 ] [ 지금 ]     │
│ [ 제목                             ]  │
│ [📎 첨부파일]  2개 첨부됨              │ ← 새로 생긴 줄
│ ┌────────────────────────────────┐   │ ← 새로 생긴 첨부 목록
│ │ [썸네일] 사진.png      120KB  × │   │
│ │ [ 📕  ] 견적서.pdf     1.2MB  × │   │
│ └────────────────────────────────┘   │
│ [ 본문                             ]  │
└──────────────────────────────────────┘
```

- **모든 파일 형식** 을 붙일 수 있습니다 (`accept` 제한 없음 — 이미지·문서·압축파일 무엇이든)
- **한 번에 여러 개** 고를 수 있습니다 (`multiple`)
- 붙인 파일은 **목록으로 표시** 되고, 오른쪽 **`×`** 로 하나씩 지울 수 있습니다
- **이미지 파일은 썸네일 미리보기** 가 뜹니다. 썸네일을 누르면 큰 화면으로 봅니다
  (손글씨 크게 보기와 같은 화면을 씁니다)
- 이미지가 아닌 파일은 종류에 맞는 아이콘이 뜹니다 — 📕PDF 📊엑셀 📄문서 🎬영상 🎵소리 🗜️압축 📎기타
- 파일 이름을 누르면 그 파일이 **열리거나 내려받아집니다**
- 상세 화면(히스토리에서 기록을 탭)에도 **`첨부파일`** 칸이 생겨서 다시 열어보고 지울 수 있습니다
  (첨부가 없는 기록에서는 이 칸이 아예 보이지 않습니다)

**한 개당 5MB 제한** 을 두었습니다. 브라우저가 앱에 내주는 저장 공간이 보통 5~10MB뿐이라,
큰 파일을 붙이면 **메모 전체가 저장되지 않는 사고** 가 납니다. 그래서

- 5MB를 넘는 파일은 붙이지 않고 `3개는 5MB를 넘어 제외` 처럼 알려줍니다
- 저장 공간이 부족하면 **방금 붙인 첨부를 자동으로 되돌리고** 안내합니다
  (메모 본문이 조용히 날아가는 일을 막기 위해서입니다)

### ② 제목 자동 생성 규칙 (요청 2)

**제목칸을 비워둔 채 저장할 때만** 아래 순서로 제목을 정합니다.

| 순위 | 조건 | 제목이 되는 것 |
|---|---|---|
| ① | 본문이 있으면 | **본문 첫 줄** (앞뒤 공백 제거, 빈 줄은 건너뜀, 40자 넘으면 `…`) |
| ② | 본문이 비고 첨부파일이 있으면 | **첫 번째 첨부파일 이름** |
| ③ | 둘 다 없으면 | 기존 그대로 (제목 없음 / 내용이 비면 저장되지 않음) |

> ★ **직접 적은 제목은 어떤 경우에도 덮어쓰지 않습니다.**
> 위 규칙은 제목칸이 비어 있을 때만 동작합니다.

적용되는 곳은 **저장 시점** 입니다 — 입력 화면의 `저장만` / `저장 및 전송` / 이메일 버튼 3개,
그리고 상세 화면의 `수정 저장` 까지 모두 같은 규칙을 씁니다.

### ③ UI는 그대로 (요청 3)

- **새로 추가한 CSS는 `.attachrow` `.attachcnt` `.files` `.file` 네 종류뿐** 입니다.
  기존 선택자(`.field` `.btn` `.cats` `.thumbs` `.item` …)는 **한 글자도 고치지 않았습니다.**
- 색·글꼴·여백은 기존 변수(`--card` `--line` `--sub` `--danger`)와
  기존 둥근 모서리 값(12px)을 그대로 씁니다.
- 첨부 버튼도 기존 `btn small` 클래스를 그대로 씁니다 (새 버튼 모양을 만들지 않았습니다).
- "개선·리팩토링·코드 정리" 목적의 수정은 하지 않았습니다.

### ④ 직접 발송(GAS)에서도 첨부파일이 함께 나갑니다

`gas/Code.20260803.v1.gs` 를 GAS 편집기에 붙여넣고 재배포하면

- 첨부파일이 **원래 파일 이름 그대로** 메일에 붙어 나갑니다 (`20260803_1432_견적서.pdf`)
- 구글 드라이브 월별 폴더에도 함께 저장됩니다
- 로그 시트 **맨 끝에 `첨부파일(개)` 열** 이 하나 늘어납니다
  (기존 열 순서는 건드리지 않았으므로 예전 기록도 그대로 읽힙니다)

> **GAS를 안 고쳐도 앱은 정상 동작합니다.** 옛 GAS는 모르는 항목(`files`)을 그냥 무시하므로
> 메일은 정상 발송되고 첨부만 빠집니다. 급하지 않으면 나중에 하셔도 됩니다.
>
> `메일앱 열기(mailto)` 방식은 원래 파일을 붙일 수 없습니다. 대신 메일 본문에
> `첨부파일 2개 (사진.png, 견적서.pdf) — 앱 히스토리에서 확인` 이라고 적어 보냅니다.

## 3. 데이터 구조가 어떻게 바뀌었나

기록 한 개(`localStorage` 안)에 **`files` 항목 하나만** 늘었습니다.

```js
{
  id: "…", category: "개인용", title: "…", body: "…",
  drawings: [ "data:image/png;base64,…" ],        // 기존 — 손글씨
  files: [                                        // ★ 오늘 추가
    { name: "견적서.pdf",
      type: "application/pdf",
      size: 1258291,
      data: "data:application/pdf;base64,…" }     // 파일 내용 자체
  ],
  createdAt: "…", savedAt: "…", updatedAt: "…", sentTo: []
}
```

### 왜 이 방식으로 정했나 (요청받은 '결정 이유')

기존 코드가 **손글씨(`drawings`)를 PNG dataURL 글자로 `localStorage` 에 넣고 있었습니다.**
첨부파일도 **똑같은 방식** 으로 맞췄고, 이유는 다음 4가지입니다.

| 이유 | 설명 |
|---|---|
| ① 서버가 없습니다 | 이 앱은 GitHub Pages(정적 호스팅)입니다. 파일을 올려둘 곳이 없으므로 기기 안에 담아야 합니다 |
| ② 기존 저장 코드가 그대로 동작 | `getRecords()` / `setRecords()` / 임시저장(`draft`) 이 JSON 하나만 다루므로 **고칠 필요가 없었습니다** |
| ③ 백업이 그대로 동작 | `JSON 내보내기 / 가져오기` 에 첨부파일이 **자동으로 포함** 됩니다 (가져오기에 `files` 한 줄만 추가) |
| ④ 오프라인에서도 열림 | 인터넷 없이도 첨부를 다시 열어볼 수 있습니다 (PWA 특성상 중요) |

**대신 생기는 한계** — base64로 담으면 용량이 약 1.33배로 늘고, 브라우저가 주는 공간은
보통 5~10MB입니다. 그래서 **한 개당 5MB 제한 + 공간 부족 시 자동 되돌리기** 를 함께 넣었습니다.
사진 몇 장·문서 몇 개 수준이면 충분하지만, **동영상처럼 큰 파일에는 맞지 않습니다.**

> 대안으로 `IndexedDB`(용량이 훨씬 큼)도 검토했지만,
> 저장·백업·복원 코드를 전부 새로 짜야 해서 **"기존 코드 구조에 맞춘다"** 는 원칙에 따라 택하지 않았습니다.
> 나중에 큰 파일이 필요해지면 그때 옮기는 것을 권합니다.

### 예전 기록은 어떻게 되나

`files` 항목이 없는 예전 기록도 **그대로 정상 동작합니다.**
읽는 쪽에서 항상 `Array.isArray(rec.files) ? rec.files : []` 로 확인하므로
따로 변환(마이그레이션)할 필요가 없습니다.

> 이미 저장소가 연결되어 있다면 **7번(갱신 방법)** 으로 바로 가세요.

### ② git 시작하고 GitHub에 연결하기 (처음 한 번만)

```powershell
cd C:\why2korea\claude\smartphone
```

### ③ 무엇이 올라갈지 눈으로 확인 (★ 건너뛰지 마세요)


아래 파일이 목록에 보이면 **멈추고** `.gitignore` 를 먼저 확인하세요.

### ④ 담고 · 저장하고 · 올리기


### 방법 B — 명령어 없이 웹에서 마우스로 올리기

2. 오른쪽 위 **`Add file`** → **`Upload files`**
3. 위 ①번을 먼저 해서 만든 **`index.html`, `sw.js`, `README.20260803.md`** 를 끌어다 놓습니다

4. 아래 칸에 설명을 적고 초록색 **`Commit changes`** 클릭

> 5번 표의 ❌ 파일이 섞이지 않았는지 직접 확인하세요.

## 7. 갱신 방법 (다음부터)

### 평소 갱신 절차

```powershell
cd C:\why2korea\claude\smartphone

# ① 새로 만든 버전 파일을 배포 이름으로 복사
Copy-Item index.20260803.v1.html index.html -Force
Copy-Item sw.20260803.v1.js      sw.js      -Force

# ② 무엇이 바뀌었는지 확인
git status
git diff --stat

# ③ 담기 → 저장 → 올리기
git add index.html sw.js README.20260803.md
git commit -m "무엇을 고쳤는지 한 줄로"
git push
```

### 버전 파일 관리 방식 (이 프로젝트 규칙)

- 원본(`index.html`)은 **직접 고치지 않습니다.**
- 고칠 때마다 `파일명.날짜.v번호.확장자` 로 **새 파일** 을 만듭니다
  → `index.20260803.v1.html`, 같은 날 두 번째면 `index.20260803.v2.html`
- 작업 전에 **먼저 폴더를 확인** 해서 같은 날짜 파일이 있는지 봅니다

  ```powershell
  Get-ChildItem C:\why2korea\claude\smartphone -Filter "*20260803*" -Recurse
  ```

- 배포할 때만 **복사해서 `index.html` 을 덮어씁니다**
- 작업 기록은 `README.날짜.md` 로 남깁니다 (같은 날 두 번째면 `README.20260803.v2.md`)

### 되돌리는 방법

```powershell
# 어제 것으로 되돌리기 — 보관본을 다시 복사하면 끝입니다
Copy-Item index.20260802.v1.html index.html -Force   # (보관본이 있는 경우)
git add index.html
git commit -m "되돌리기"
git push

# 또는 git 기록으로 되돌리기
git log --oneline          # 되돌아갈 지점의 앞 7글자를 확인
git checkout <7글자> -- index.html
git commit -m "index.html 되돌리기"
git push
```

### ⚠️ 앱 코드를 고칠 때마다 반드시 — `sw.js` 버전 올리기

```js
const CACHE_NAME = 'why2korea-memo-v5';   // 다음에 고치면 v6, 그다음 v7 …
```

빠뜨리면 **휴대폰이 옛 화면을 계속 보여줍니다.**
오늘은 이미 `v5` 로 올려두었으니, 다음 작업 때 `v6` 으로 올리면 됩니다.

### GAS(직접 발송)를 쓰신다면 — 재배포까지 해야 반영됩니다

## 8. 올린 뒤 확인 순서

1. **1~2분 기다립니다** (GitHub Pages 배포 시간)
2. PC 크롬에서 https://why2korea.github.io/smartphone_idea_logging/ 접속 → `Ctrl+Shift+R`
3. 휴대폰에서 앱을 **완전히 종료했다가** 다시 엽니다 (최근 앱 목록에서 밀어서 닫기)
4. 아래를 눈으로 확인합니다

   | 확인할 것 | 정상이라면 |
   |---|---|
   | 입력 화면 | 제목칸 **바로 아래** 에 `📎 첨부파일` 버튼이 보인다 |
   | 여러 개 첨부 | 파일 고르기에서 여러 개를 한 번에 고를 수 있다 |
   | 썸네일 | 사진을 붙이면 **작은 미리보기** 가 뜨고, 누르면 크게 보인다 |
   | 개별 삭제 | 오른쪽 `×` 를 누르면 그 파일만 지워진다 |
   | 제목 자동 ① | 제목을 비우고 본문만 쓰고 저장 → 히스토리 제목이 **본문 첫 줄** |
   | 제목 자동 ② | 제목·본문 모두 비우고 **파일만** 붙여 저장 → 제목이 **파일 이름** |
   | 제목 유지 | 제목을 직접 쓰면 → 그 제목이 **그대로** 남는다 |
   | 복원 | 히스토리 → 기록을 탭 → `첨부파일` 칸에 파일이 그대로 있다 |
   | 다른 UI | 분류 버튼·날짜줄·본문·저장 버튼 모양이 **어제와 똑같다** |

## 9. 확인한 것 / 못 한 것

`jsdom`(브라우저 흉내 도구)으로 앱을 실제로 실행해 **25가지를 자동 검사했고 모두 통과** 했습니다.

| | 내용 |
|---|---|
| ✅ 확인함 | 자바스크립트 문법 오류 없음 (`index`·`gas` 둘 다) |
| ✅ 확인함 | 코드가 참조하는 화면 요소 id 81개 모두 실제로 존재 |
| ✅ 확인함 | 첨부 UI가 **제목칸과 본문칸 사이** 에 있음 |
| ✅ 확인함 | `multiple` 있음 · `accept` 제한 없음 (모든 형식 허용) |
| ✅ 확인함 | 여러 개 첨부 → 목록 표시 → 개별 삭제 |
| ✅ 확인함 | 이미지는 썸네일 / 그 외는 아이콘 |
| ✅ 확인함 | 5MB 초과 파일은 제외하고 안내 |
| ✅ 확인함 | 저장 → 히스토리 → 상세에서 첨부가 **그대로 복원** |
| ✅ 확인함 | 제목 자동 생성 3가지 우선순위 + **직접 쓴 제목은 안 덮어씀** |
| ✅ 확인함 | 저장 공간 부족 시 **첨부가 자동으로 되돌려짐** (본문이 날아가지 않음) |
| ✅ 확인함 | `files` 가 없는 **예전 기록도 정상 동작** (목록·상세·수정 저장) |
| ✅ 확인함 | 기존 CSS 선택자 **한 개도 수정하지 않음** (새 선택자 4종만 추가) |
| ⚠️ 못 함 | **실제 폰 화면 렌더링** (PC에 브라우저 자동화 도구가 없음) → 폰에서 눈으로 봐주세요 |
| ⚠️ 못 함 | **GAS 실제 발송** (배포·권한이 필요) → 재배포 후 `연결 테스트` 와 실제 발송 1회를 해보세요 |

### 남아 있는 확인 사항

- [ ] 아이폰에서 파일 이름을 눌렀을 때 **내려받기가 되는지** (사파리는 dataURL 내려받기가 제한될 수 있습니다)
- [ ] 사진 여러 장을 붙였을 때 **저장 공간 경고** 가 언제 뜨는지 (기기마다 한도가 다릅니다)
- [ ] GAS 재배포 후 첨부파일이 **원래 이름으로** 메일에 붙는지
