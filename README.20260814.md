## 2. 반영 내역 ① — 앱이 꺼져 있어도 울리는 알람

### 2-1. 왜 예전에는 앱을 켜 두어야만 울렸나

어제까지의 알람은 **앱 화면 안에서 15초마다 시계를 보는 방식**이었습니다.
앱을 닫으면 그 시계도 함께 멈추니, 당연히 울릴 수가 없었습니다.

### 2-2. 이번에 바꾼 방식 (웹/PWA 표준 방식)

이 앱은 **웹앱(PWA)** 입니다. 안드로이드 네이티브 앱이 아니므로
`AlarmManager` 같은 것은 쓸 수 없고, 웹 표준인
**서비스워커(Service Worker) + 알림(Notification) API** 로 전환했습니다.

```
   [앱 화면 index.html]                     [서비스워커 sw.js]
   메모를 저장할 때마다                       (앱과 따로 도는 프로그램)
        │                                          │
        └── 알람 목록을 옮겨 적음 ──▶ IndexedDB ──▶ 읽어서 시각이 되면
                                    'why2korea_alarm'    휴대폰 알림을 띄움
                                                          │
                                            ◀── "울렸어요" 라고 알려줌 ──┘
```

**왜 IndexedDB 인가?**
앱 화면과 서비스워커는 서로 다른 프로그램이라 `localStorage` 를 함께 볼 수 없습니다.
둘 다 볼 수 있는 창고가 IndexedDB 뿐이라서 알람 목록만 그쪽으로 옮겨 적습니다.
(**기록 본문은 그대로 `localStorage` 에 있습니다. 저장 방식을 바꾸지 않았습니다.**)

### 2-3. 서비스워커가 깨어나는 4가지 통로

브라우저는 서비스워커를 계속 켜 두지 않습니다. 그래서 **깨어날 수 있는 통로를 모두** 걸어 두었습니다.

| | 통로 | 언제 깨어나나 | 크롬(안드로이드)에서 |
|---|---|---|---|
| ① | **예약 알림** (Notification Triggers) | 시각을 미리 예약 → OS가 알아서 띄움 | ❌ **아직 지원 안 함** (확인함) |
| ② | **주기 백그라운드 동기화** (Periodic Background Sync) | 브라우저가 몇 시간에 한 번 깨워 줌 | ⭕ 설치한 PWA 에서만 |
| ③ | **앱을 내리는 순간 붙잡아 두기** | 화면 밖으로 나갈 때 최대 5분 대기 | ⭕ |
| ④ | **뒤늦게 확인** (catch-up) | 앱/서비스워커가 다음에 깨어날 때 | ⭕ 항상 |

> ①번이 되면 100% 정확했겠지만, 실제로 크롬에서 `showTrigger` 지원 여부를 확인해 보니
> **false(미지원)** 였습니다. 그래서 코드는 넣어 두되(나중에 지원되면 자동으로 켜집니다)
> 실제로는 ②③④ 로 동작합니다. → 자세한 한계는 **4장**을 꼭 읽어 주세요.

### 2-4. 어디가 어떻게 바뀌었나 (코드 위치)

**`sw.js` — `[4] 알람 엔진` 통째로 새로 추가**

| 함수 | 하는 일 |
|---|---|
| `alarmOpenDB / alarmReadAll / alarmWriteMany` | IndexedDB 창고 읽고 쓰기 |
| `alarmShow(item, late)` | 휴대폰 알림 하나 띄우기 (진동·아이콘·본문 포함) |
| `alarmScheduleTriggers()` | ①번 예약 알림 걸기 (지원하는 브라우저에서만) |
| `alarmFireDue()` | 시각이 지난 알람을 찾아 알림을 띄우고 `fired` 표시 |
| `alarmWakeup()` | 깨어날 때마다 ①+② 를 한 번에 처리 |
| `alarmHoldUntilNext()` | 5분 안에 울릴 알람이면 그때까지 붙잡아 두기 |
| `notificationclick` | 알림을 누르면 앱이 열리고 **그 메모 상세 화면**으로 이동 |
| `notificationclose` | 알림을 쓸어서 지워도 '울렸음' 으로 처리 (두 번 안 울리게) |

**`index.html` — `[7-C]` 절 새로 추가 + `[7-B]` 손봄**

| 함수 | 하는 일 |
|---|---|
| `notifyPermission()` | 알림 권한 상태 확인 |
| `requestNotifyPermission()` | **알람 체크를 켠 그 순간** 알림 권한을 물어봄 |
| `buildAlarmRows()` | 기록 → 창고에 적을 알람 줄 만들기 |
| `syncAlarmsToSW()` / `queueAlarmSync()` | 창고에 옮겨 적고 서비스워커에게 알림 |
| `pullFiredFromSW()` | 서비스워커가 울린 알람을 기록에 반영 (팝업 중복 방지) |
| `pushAlarmNotification()` | 앱이 화면 밖일 때는 팝업 대신 휴대폰 알림으로 |
| `registerPeriodicAlarmCheck()` | ②번 주기 동기화 신청 |
| `listenToSW()` / `openAlarmFromUrl()` | 알림을 눌렀을 때 그 메모 열기 |

> `setRecords()` 를 한 줄 감쌌습니다. **기록을 저장하는 모든 경로**(새로 저장·수정 저장·
> 삭제·전체 삭제·가져오기)에서 알람 목록이 자동으로 창고에 반영됩니다.

### 2-5. 두 번 울리지 않게 하는 장치

| 상황 | 어떻게 막나 |
|---|---|
| 서비스워커가 울림 → 나중에 앱을 염 | 창고의 `fired` 를 기록의 `alarmFiredAt` 으로 옮겨 적음 |
| 앱 팝업이 떴는데 서비스워커도 울림 | 알림에 같은 `tag` 를 붙여 하나로 합쳐짐 |
| 알람 시각을 바꿈 | 창고의 `fired`·`armed` 표시를 지워 **새 시각에 다시 울림** |

## 3. 반영 내역 ② — 히스토리 목록의 알람 표시

하단 **히스토리** 화면의 각 메모 줄에, 분류 배지 옆에 알람 배지가 붙습니다.

| 보이는 모습 | 뜻 |
|---|---|
| `⏰ 14:30` (노란 테두리) | **오늘** 14:30 에 울릴 알람이 걸려 있음 |
| `⏰ 8-16(토) 09:00` (노란 테두리) | 다른 날에 울릴 알람이 걸려 있음 |
| `⏰ 09:16 울림` (흐린 테두리) | 이미 울렸거나 시각이 지난 알람 |
| (아무 표시 없음) | 알람을 걸지 않은 메모 |

- 알람 체크를 **끈** 메모에는 표시가 나오지 않습니다. (시각만 적어 둔 상태)
- 배지를 길게 누르면(또는 PC에서 마우스를 올리면) `알람: 2026-08-16 (토) 09:00` 전체 시각이 보입니다.
- **화면 구성·버튼·순서는 하나도 바꾸지 않았습니다.** 배지 한 개만 추가했습니다.

## 4. 어디까지 되고 어디부터 안 되는가 (아주 중요)

솔직하게 적습니다. **브라우저(크롬)의 제약** 때문에 100% 정시 알람은 보장되지 않습니다.

| 상황 | 결과 |
|---|---|
| 앱이 화면에 열려 있음 | ⭕ **정시에** 앱 안 팝업 |
| 앱은 켜져 있고 화면만 껐거나 다른 앱을 봄 (5분 이내) | ⭕ **정시에** 휴대폰 알림 |
| 앱을 최근 앱에서 밀어 껐음 / 오래 안 씀 | 🔺 **정시에 못 울릴 수 있음** — 브라우저가 서비스워커를 깨워 줄 때 울립니다 (몇 분~몇 시간 늦을 수 있음) |
| 알림 권한을 거부함 | 🔺 예전과 같음 — 앱을 다시 열 때 '⏰ 지난 알람' 으로 |
| 폰을 껐다 켬 | 🔺 앱을 한 번 열면 그때 지난 알람을 알려줍니다 |

### 왜 100% 가 안 되나

- 웹앱은 안드로이드 네이티브 앱의 `AlarmManager` 를 쓸 수 없습니다.
- 웹 표준의 정시 예약 기능(**Notification Triggers**)은 **크롬이 아직 지원하지 않습니다.**
  (오늘 실제로 확인 → `showTrigger` = false)

### 100% 정시로 만들고 싶다면 (다음에 할 수 있는 선택지)

| 방법 | 정확도 | 드는 일 |
|---|---|---|
| **A. 구글 앱스 스크립트(GAS) 가 시각에 맞춰 메일 발송** | ⭕ 매우 높음 | GAS 에 1분짜리 시간 트리거 + **알람 전용 새 시트** 1개. Gmail 앱 알림으로 울림 |
| **B. Web Push 서버 구축** | ⭕ 매우 높음 | 푸시 서버(VAPID) 가 따로 필요 — GAS 로는 어려움 |
| **C. 크롬이 Notification Triggers 를 지원할 때까지 대기** | ⭕ | **코드는 이미 넣어 두었습니다.** 지원되면 자동으로 켜집니다 |

> **A 안이 현실적입니다.** 다만 "메일 전송 기록 시트는 건드리지 말라"고 하셔서
> 이번에는 하지 않았습니다. (기존 시트가 아니라 **별도의 새 시트**를 쓰게 됩니다)

| **버튼·화면·첨부파일 UI 는 그대로** | 요청하신 범위(알람 로직만)를 지켰습니다 |
| **상세 화면 안내문 한 문장만 수정** | "앱이 열려 있을 때만 울립니다" 가 이제 사실이 아니게 되어 그대로 두면 오히려 오해를 만듭니다. 문구만 고치고 화면 구성은 그대로입니다 |
| **`sw.js` 캐시 이름 v8 → v9** | 안 올리면 폰이 옛 서비스워커를 계속 써서 알람 엔진이 들어가지 않습니다 |
| **히스토리 배지는 '분류 배지 옆'** | 이미 📌 고정 / ✓ 확인함 / ✓ 전송 배지가 있는 자리라 새 줄을 만들 필요가 없습니다 |

## 12. 줄바꿈(CRLF) 경고에 대하여 — 2026-08-14 추가

`git add .` 를 하면 모든 파일에 대해 아래 경고가 나옵니다.

```
warning: in the working copy of 'README.md', LF will be replaced by CRLF the next time Git touches it
```

### 결론: 문제 없습니다

| 확인한 것 | 결과 |
|---|---|
| 원인 | Git for Windows 설치 시 자동으로 켜지는 `core.autocrlf=true` (전역 설정) |
| 작업 폴더의 파일 | 전부 **LF** |
| **git 저장소에 실제로 들어간 내용** | 전부 **LF** (`index.html` 165,937바이트로 작업본과 1바이트도 다르지 않음) |
| GitHub Pages 로 배포되는 내용 | **LF 그대로** — 앱 동작에 영향 없음 |

경고의 뜻은 **"저장소에는 LF 로 넣지만, 나중에 이 파일을 *꺼낼 때*(clone/checkout)
윈도우식 CRLF 로 바꿔서 써 주겠다"** 입니다. 내용이 망가진다는 뜻이 아닙니다.
HTML·JS·MD 는 CRLF 든 LF 든 똑같이 동작하므로 **그대로 커밋·푸시해도 됩니다.**

### 그래도 경고가 성가셔서 `.gitattributes` 를 추가했습니다

```
* text=auto eol=lf     ← 글자 파일은 전부 LF 로 통일
*.png  binary          ← 그림은 손대지 않음 (건드리면 깨집니다)
*.jpg  binary
```

확인한 것:

- 추가한 뒤 `git add .` 를 다시 해 보니 **경고가 나오지 않습니다.**
- 저장된 내용은 여전히 **LF** 입니다. (`index.html` / `sw.js` / `README.md` 모두 확인)
- 아이콘 3개와 `mic error.jpg` 는 크기가 그대로여서 **깨지지 않았음을 확인**했습니다.
  (`icon-192.png` 1,213 / `icon-512.png` 3,573 / `mic error.jpg` 160,565 바이트)
- 이 파일도 **GitHub 에 함께 올려야** 다른 PC 에서 받을 때도 같은 규칙이 적용됩니다.

> 참고: `.gitattributes` 없이 경고만 없애고 싶다면 아래 방법도 있습니다.
> ```
> git config --global core.autocrlf input
> ```
> 다만 이 방법은 **내 PC 에만** 적용되므로, 저장소에 같이 올라가는
> `.gitattributes` 쪽이 더 확실합니다.
