## 1. 폰에서 직접 확인한 것 (원인 규명)

폰을 USB로 연결하고 크롬 원격 디버깅으로 **실제 측정**했습니다.

### 1-1. 설정은 전부 정상이었습니다

| 확인 항목 | 결과 |
|---|---|
| 설치앱(PWA) 안 알림 권한 | ✅ `granted` |
| `periodicSync` 등록 | ✅ `w2k-alarm-check` |
| 서비스워커 | ✅ `activated` (앱을 닫아도 살아 있음) |
| 새 코드 적용 | ✅ |

> **함정 하나:** 크롬 **탭**에서 열면 권한이 `prompt`(미허용)로 나오고,
> **설치앱**에서 열면 `granted` 입니다. **둘은 별개**입니다.
> 그래서 테스트는 반드시 **홈 화면 아이콘(설치앱)** 으로 해야 합니다.

### 1-2. 그런데도 앱을 닫으면 안 울렸습니다

- 10:22 알람 등록 → 앱 완전 종료 → **알림 없음** ❌
- 실제 기록에서도 10:05 알람이 `firedAt=10:07:38` (앱을 연 순간에야 뒤늦게 처리)

### 1-3. 진짜 원인

**크롬은 웹앱이 "몇 시에 깨워달라"고 스스로 예약하는 것을 허용하지 않습니다.**

| 시도해 본 방법 | 결과 |
|---|---|
| 예약 알림 (Notification Triggers) | ❌ Chrome 150 미지원 (`showTrigger` = false) |
| 서비스워커가 스스로 기다리기 | ❌ 크롬이 30초 정도면 서비스워커를 재웁니다 |
| 주기 백그라운드 동기화 | 🔺 브라우저 마음대로 (몇 시간에 한 번) |
| 안드로이드 시계앱에 넘기기 (`intent://`) | ❌ **실제 손가락 터치로도** 크롬이 차단 |

### 1-4. 결정적 증거

서비스워커에 **푸시 신호를 넣어 봤더니** — 앱이 완전히 닫힌 상태에서

```
⏰ 알람 — ⏰테스트 10:22     ← 알림이 즉시 떴습니다 ✅
```

**즉, 알람 로직은 처음부터 완벽했습니다.**
빠진 것은 오직 **"시각이 됐을 때 폰을 깨워 줄 바깥쪽 신호"** 하나였습니다.

## 2. 해결 방법 — 웹 푸시

```
 [폰: 앱]      알람 저장
                  │  구독주소 + 서명 + 알람시각 만 보냄
                  ▼
 [GAS]        1분마다 확인 → 시각이 된 알람이 있으면 푸시 발송
                  │
                  ▼
 [구글 푸시서버] ─────────────────▶ [폰: 서비스워커] 깨어남
                                          │ IndexedDB 를 읽어
                                          ▼
                                    ⏰ 알람 — 메모제목
                                    (누르면 그 메모가 열립니다)
```

### 2-1. 1차 검증 — 푸시만 따로 시험 (2026-08-14 10:40)

앱을 **완전히 종료(force-stop)** 한 뒤, GAS가 보낼 것과 **완전히 똑같은 요청**을 PC에서 발사:

```
HTTP 201 Created                      ← 푸시 접수됨
⏰ 알람 — ⏰테스트 10:40                ← 폰에 알림 발생 ✅
tag = w2k-alarm-TEST-mssa1i0b          ← 정확히 그 알람
```

**앱이 꺼져 있어도 정시에 울리는 것을 폰에서 확인했습니다.**


### 2-2. ★ 최종 검증 — GAS 경유 실제 동작 (2026-08-14 11:00) ★

GAS 코드 붙여넣기 + `알람푸시_설치()` 트리거 생성 + 웹앱 재배포를 마친 뒤,
**PC가 전혀 개입하지 않는 상태**에서 실제와 똑같이 시험했습니다.

| 시각 | 일어난 일 |
|---|---|
| 10:55:27 | 앱 **완전 종료** (force-stop — 최근앱에서 밀어낸 것과 동일) |
| 11:00:00 | 알람 시각 |
| **11:00:54** | **`⏰ 알람 — ⏰테스트 11:00` 알림 발생** ← GAS 트리거가 푸시 발송 |
| 11:01:25 | 확인 |

- **지연 54초** — GAS가 1분마다 확인하므로 예상 범위 안입니다.
- **앱이 정말 죽어 있었다는 증거:** 알림이 뜬 시점의 앱 프로세스 생존시간이 **59초**였습니다.
  10:55 에 종료된 뒤 죽어 있다가 **푸시가 앱을 깨워서** 되살아난 것입니다.

```
앱 → GAS 등록      {"ok":true,"count":2}   ✅
GAS 1분 트리거 → 푸시 발송                  ✅
푸시 → 서비스워커 깨움 → 알림 표시           ✅
```

> **결론: 앱이 완전히 꺼져 있어도 알람이 울립니다. 목표 달성.**

### 2-3. 암호화가 필요 없는 이유 (그래서 GAS로 가능합니다)

푸시에는 **내용을 싣지 않습니다.** 그냥 "깨어나"라는 빈 신호만 보냅니다.
알림 문구(제목·분류·시각)는 **폰 안의 서비스워커가 IndexedDB를 읽어 스스로** 만듭니다.

- 덕분에 GAS가 어려운 암호화(aes128gcm)를 할 필요가 전혀 없습니다.
- 덕분에 **메모 제목·본문이 GAS로 나가지 않습니다.** (개인정보 안전)

### 2-4. 서명(VAPID)은 폰이 만듭니다

푸시 서버는 "네가 보낸 게 맞냐"를 **ES256 전자서명**으로 확인합니다.
GAS는 이 서명을 만들 수 없어서(구글 앱스 스크립트에 ECDSA 기능이 없음),

- **폰이 서명을 만들어 GAS에 맡기고**, GAS는 그것을 그대로 붙여서 보냅니다.
- 서명에 쓰는 **개인열쇠는 폰 밖으로 절대 나가지 않습니다.**
- 서명은 규격상 **최대 24시간**짜리라, 앱을 열 때마다 새로 만들어 올립니다.
  추가로 **서비스워커가 주기적으로도 갱신**하도록 넣어 두었습니다.

## 4. ★ GAS 설치 (10분, 한 번만) — ✅ 2026-08-14 완료·검증됨

> ✅ **2026-08-14 설치 완료 및 동작 확인됨.** 아래 내용은 다시 설치해야 할 때를 위한 기록입니다.
> (새 폰으로 바꾸거나 GAS 프로젝트를 다시 만들 때 그대로 따라 하시면 됩니다)


이 설치를 하지 않으면 알람은 앱을 열 때만 울립니다. (설치 전 상태)

### 1단계 — GAS 코드 교체

1. 크롬에서 https://script.google.com 접속 → **why2korea_memo** 프로젝트 열기
2. 왼쪽 `Code.gs` 클릭 → 편집창의 **내용을 전부 지우기** (Ctrl+A → Delete)
3. PC의 `C:\why2korea\claude\smartphone\gas\Code.gs` 를 메모장으로 열어
   **전체 복사(Ctrl+A → Ctrl+C)** → GAS 편집창에 **붙여넣기(Ctrl+V)**
4. **저장** (Ctrl+S)

### 2단계 — 1분 트리거 만들기 (가장 중요)

1. GAS 편집창 위쪽의 **함수 선택 드롭다운**(보통 `doPost` 라고 되어 있음)을 클릭
2. 목록에서 **`알람푸시_설치`** 를 고릅니다
3. **▶ 실행** 버튼 클릭
4. 권한 승인 창이 뜨면
   → **[권한 검토]** → 본인 구글 계정 선택
   → "Google에서 확인하지 않은 앱" 경고가 나오면
     **[고급]** → 맨 아래 **[why2korea_memo(안전하지 않음)으로 이동]** → **[허용]**
5. 아래 실행 로그에 **`설치 완료 — 1분마다 알람을 확인합니다.`** 가 나오면 성공

> 이 트리거가 **1분마다 자동으로 돌면서** 알람 시각을 확인합니다.
> 구글 무료 계정의 트리거 실행 한도(하루 90분) 안에서 충분히 돌아갑니다.

### 3단계 — 웹앱 재배포 (앱이 GAS와 통신하려면 필수)

1. 오른쪽 위 **[배포]** → **[배포 관리]**
2. 기존 배포 옆의 **연필(수정)** 아이콘 클릭
3. **버전: `새 버전`** 선택 → **[배포]**
4. **URL은 그대로 유지됩니다.** 앱 설정을 다시 만질 필요 없습니다.

### 4단계 — 폰에서 확인

1. 홈 화면의 **why2korea_memo 아이콘**으로 앱을 엽니다 (크롬 탭 말고!)
2. 아무 메모나 하나 쓰고 **⏰ 알람**을 **3분 뒤**로 걸어 저장합니다
3. **최근 앱에서 밀어서 앱을 완전히 종료**합니다
4. 3분 뒤 **⏰ 알람 — (메모제목)** 알림이 뜨면 **성공**입니다

### 5단계 — 잘 안 되면 GAS에서 점검

GAS 편집창에서 함수 드롭다운 → **`알람푸시_상태보기`** → **▶ 실행** → 로그 확인

```
1분 트리거: 있음 ✅

폰 1 (a1b2c3...)
  마지막 갱신 : 2026-08-14T11:05:00.000Z
  푸시 주소   : https://fcm.googleapis.com/fcm/send/...
  대기중 알람 : 2개
     · 08-15 06:00
```

- **"1분 트리거: 없음 ❌"** → 2단계를 다시 하세요
- **"아직 등록된 폰이 없습니다"** → 3단계(재배포)를 안 했거나, 폰에서 앱을 열고 알람을 저장하지 않았습니다
- 즉시 시험하려면 **`알람푸시_지금테스트`** 를 실행하면 바로 푸시가 날아갑니다

### 6단계 — 폰 배터리 설정 (1차 작업 문서와 동일)

- 설정 → 앱 → why2korea_memo → **배터리** → **`제한 없음`**
- 설정 → 배터리 → **백그라운드 사용 제한** → `사용하지 않는 앱을 절전 상태로 전환` **끄기**
- 설정 → 알림 → **방해 금지**를 쓰신다면 예외 앱에 추가

## 5. 개인정보는 어떻게 되나

| 항목 | 어디에 있나 |
|---|---|
| 메모 제목·본문·첨부 | **폰 안에만** (localStorage) — GAS로 안 나갑니다 |
| 알림에 뜨는 문구 | **폰 안에서 생성** (IndexedDB를 읽어 서비스워커가 만듦) |
| 서명용 개인열쇠 | **폰 안에만** (IndexedDB) — 절대 안 나갑니다 |
| GAS로 보내는 것 | 구독 주소 + 서명 + **알람 시각(숫자)** + 알람 id — 이게 전부입니다 |
| GAS가 저장하는 곳 | **스크립트 속성** (스프레드시트 아님) |

> 푸시 본문이 비어 있으므로, 중간에 누가 가로채도 **메모 내용을 알 수 없습니다.**

## 6. 올릴 파일 / 올리면 안 되는 파일

### ✅ 올려야 하는 파일 (1차 문서와 동일 + 아래)

| 파일 | 왜 |

## 2. 반영 내역 ① — 앱이 꺼져 있어도 울리는 알람

### 2-1. 왜 예전에는 앱을 켜 두어야만 울렸나

어제까지의 알람은 **앱 화면 안에서 15초마다 시계를 보는 방식**이었습니다.
앱을 닫으면 그 시계도 함께 멈추니, 당연히 울릴 수가 없었습니다.

### 2-2. 이번에 바꾼 방식 (웹/PWA 표준 방식)

이 앱은 **웹앱(PWA)** 입니다. 안드로이드 네이티브 앱이 아니므로
`AlarmManager` 같은 것은 쓸 수 없고, 웹 표준인
**서비스워커(Service Worker) + 알림(Notification) API** 로 전환했습니다.

```
   [앱 화면 index.html]                     [서비스워커 sw.js]
   메모를 저장할 때마다                       (앱과 따로 도는 프로그램)
        │                                          │
        └── 알람 목록을 옮겨 적음 ──▶ IndexedDB ──▶ 읽어서 시각이 되면
                                    'why2korea_alarm'    휴대폰 알림을 띄움
                                                          │
                                            ◀── "울렸어요" 라고 알려줌 ──┘
```

**왜 IndexedDB 인가?**
앱 화면과 서비스워커는 서로 다른 프로그램이라 `localStorage` 를 함께 볼 수 없습니다.
둘 다 볼 수 있는 창고가 IndexedDB 뿐이라서 알람 목록만 그쪽으로 옮겨 적습니다.
(**기록 본문은 그대로 `localStorage` 에 있습니다. 저장 방식을 바꾸지 않았습니다.**)

### 2-3. 서비스워커가 깨어나는 4가지 통로

브라우저는 서비스워커를 계속 켜 두지 않습니다. 그래서 **깨어날 수 있는 통로를 모두** 걸어 두었습니다.

| | 통로 | 언제 깨어나나 | 크롬(안드로이드)에서 |
|---|---|---|---|
| ① | **예약 알림** (Notification Triggers) | 시각을 미리 예약 → OS가 알아서 띄움 | ❌ **아직 지원 안 함** (확인함) |
| ② | **주기 백그라운드 동기화** (Periodic Background Sync) | 브라우저가 몇 시간에 한 번 깨워 줌 | ⭕ 설치한 PWA 에서만 |
| ③ | **앱을 내리는 순간 붙잡아 두기** | 화면 밖으로 나갈 때 최대 5분 대기 | ⭕ |
| ④ | **뒤늦게 확인** (catch-up) | 앱/서비스워커가 다음에 깨어날 때 | ⭕ 항상 |

> ①번이 되면 100% 정확했겠지만, 실제로 크롬에서 `showTrigger` 지원 여부를 확인해 보니
> **false(미지원)** 였습니다. 그래서 코드는 넣어 두되(나중에 지원되면 자동으로 켜집니다)
> 실제로는 ②③④ 로 동작합니다. → 자세한 한계는 **4장**을 꼭 읽어 주세요.

### 2-4. 어디가 어떻게 바뀌었나 (코드 위치)

**`sw.js` — `[4] 알람 엔진` 통째로 새로 추가**

| 함수 | 하는 일 |
|---|---|
| `alarmOpenDB / alarmReadAll / alarmWriteMany` | IndexedDB 창고 읽고 쓰기 |
| `alarmShow(item, late)` | 휴대폰 알림 하나 띄우기 (진동·아이콘·본문 포함) |
| `alarmScheduleTriggers()` | ①번 예약 알림 걸기 (지원하는 브라우저에서만) |
| `alarmFireDue()` | 시각이 지난 알람을 찾아 알림을 띄우고 `fired` 표시 |
| `alarmWakeup()` | 깨어날 때마다 ①+② 를 한 번에 처리 |
| `alarmHoldUntilNext()` | 5분 안에 울릴 알람이면 그때까지 붙잡아 두기 |
| `notificationclick` | 알림을 누르면 앱이 열리고 **그 메모 상세 화면**으로 이동 |
| `notificationclose` | 알림을 쓸어서 지워도 '울렸음' 으로 처리 (두 번 안 울리게) |

**`index.html` — `[7-C]` 절 새로 추가 + `[7-B]` 손봄**

| 함수 | 하는 일 |
|---|---|
| `notifyPermission()` | 알림 권한 상태 확인 |
| `requestNotifyPermission()` | **알람 체크를 켠 그 순간** 알림 권한을 물어봄 |
| `buildAlarmRows()` | 기록 → 창고에 적을 알람 줄 만들기 |
| `syncAlarmsToSW()` / `queueAlarmSync()` | 창고에 옮겨 적고 서비스워커에게 알림 |
| `pullFiredFromSW()` | 서비스워커가 울린 알람을 기록에 반영 (팝업 중복 방지) |
| `pushAlarmNotification()` | 앱이 화면 밖일 때는 팝업 대신 휴대폰 알림으로 |
| `registerPeriodicAlarmCheck()` | ②번 주기 동기화 신청 |
| `listenToSW()` / `openAlarmFromUrl()` | 알림을 눌렀을 때 그 메모 열기 |

> `setRecords()` 를 한 줄 감쌌습니다. **기록을 저장하는 모든 경로**(새로 저장·수정 저장·
> 삭제·전체 삭제·가져오기)에서 알람 목록이 자동으로 창고에 반영됩니다.

### 2-5. 두 번 울리지 않게 하는 장치

| 상황 | 어떻게 막나 |
|---|---|
| 서비스워커가 울림 → 나중에 앱을 염 | 창고의 `fired` 를 기록의 `alarmFiredAt` 으로 옮겨 적음 |
| 앱 팝업이 떴는데 서비스워커도 울림 | 알림에 같은 `tag` 를 붙여 하나로 합쳐짐 |
| 알람 시각을 바꿈 | 창고의 `fired`·`armed` 표시를 지워 **새 시각에 다시 울림** |

## 3. 반영 내역 ② — 히스토리 목록의 알람 표시

하단 **히스토리** 화면의 각 메모 줄에, 분류 배지 옆에 알람 배지가 붙습니다.

| `⏰ 8-16(토) 09:00` (노란 테두리) | 다른 날에 울릴 알람이 걸려 있음 |

| (아무 표시 없음) | 알람을 걸지 않은 메모 |

- 알람 체크를 **끈** 메모에는 표시가 나오지 않습니다. (시각만 적어 둔 상태)
- 배지를 길게 누르면(또는 PC에서 마우스를 올리면) `알람: 2026-08-16 (토) 09:00` 전체 시각이 보입니다.
- **화면 구성·버튼·순서는 하나도 바꾸지 않았습니다.** 배지 한 개만 추가했습니다.

## 4. 어디까지 되고 어디부터 안 되는가 (아주 중요)

솔직하게 적습니다. **브라우저(크롬)의 제약** 때문에 100% 정시 알람은 보장되지 않습니다.

| 상황 | 결과 |
|---|---|
| 앱이 화면에 열려 있음 | ⭕ **정시에** 앱 안 팝업 |
| 앱은 켜져 있고 화면만 껐거나 다른 앱을 봄 (5분 이내) | ⭕ **정시에** 휴대폰 알림 |
| 앱을 최근 앱에서 밀어 껐음 / 오래 안 씀 | 🔺 **정시에 못 울릴 수 있음** — 브라우저가 서비스워커를 깨워 줄 때 울립니다 (몇 분~몇 시간 늦을 수 있음) |
| 알림 권한을 거부함 | 🔺 예전과 같음 — 앱을 다시 열 때 '⏰ 지난 알람' 으로 |
| 폰을 껐다 켬 | 🔺 앱을 한 번 열면 그때 지난 알람을 알려줍니다 |

### 왜 100% 가 안 되나

- 웹앱은 안드로이드 네이티브 앱의 `AlarmManager` 를 쓸 수 없습니다.
- 웹 표준의 정시 예약 기능(**Notification Triggers**)은 **크롬이 아직 지원하지 않습니다.**
  (오늘 실제로 확인 → `showTrigger` = false)

### 100% 정시로 만들고 싶다면 (다음에 할 수 있는 선택지)

| 방법 | 정확도 | 드는 일 |
|---|---|---|

## 12. 줄바꿈(CRLF) 경고에 대하여 — 2026-08-14 추가

`git add .` 를 하면 모든 파일에 대해 아래 경고가 나옵니다.

```
warning: in the working copy of 'README.md', LF will be replaced by CRLF the next time Git touches it
```

### 결론: 문제 없습니다

| 확인한 것 | 결과 |
|---|---|
| 원인 | Git for Windows 설치 시 자동으로 켜지는 `core.autocrlf=true` (전역 설정) |
| 작업 폴더의 파일 | 전부 **LF** |
| **git 저장소에 실제로 들어간 내용** | 전부 **LF** (`index.html` 165,937바이트로 작업본과 1바이트도 다르지 않음) |
| GitHub Pages 로 배포되는 내용 | **LF 그대로** — 앱 동작에 영향 없음 |

경고의 뜻은 **"저장소에는 LF 로 넣지만, 나중에 이 파일을 *꺼낼 때*(clone/checkout)
윈도우식 CRLF 로 바꿔서 써 주겠다"** 입니다. 내용이 망가진다는 뜻이 아닙니다.
HTML·JS·MD 는 CRLF 든 LF 든 똑같이 동작하므로 **그대로 커밋·푸시해도 됩니다.**

### 그래도 경고가 성가셔서 `.gitattributes` 를 추가했습니다

```
* text=auto eol=lf     ← 글자 파일은 전부 LF 로 통일
*.png  binary          ← 그림은 손대지 않음 (건드리면 깨집니다)
*.jpg  binary
```

확인한 것:

- 추가한 뒤 `git add .` 를 다시 해 보니 **경고가 나오지 않습니다.**
- 저장된 내용은 여전히 **LF** 입니다. (`index.html` / `sw.js` / `README.md` 모두 확인)
- 아이콘 3개와 `mic error.jpg` 는 크기가 그대로여서 **깨지지 않았음을 확인**했습니다.
  (`icon-192.png` 1,213 / `icon-512.png` 3,573 / `mic error.jpg` 160,565 바이트)
- 이 파일도 **GitHub 에 함께 올려야** 다른 PC 에서 받을 때도 같은 규칙이 적용됩니다.

> 참고: `.gitattributes` 없이 경고만 없애고 싶다면 아래 방법도 있습니다.
> ```
> git config --global core.autocrlf input
> ```
> 다만 이 방법은 **내 PC 에만** 적용되므로, 저장소에 같이 올라가는
> `.gitattributes` 쪽이 더 확실합니다.

## 4. 판단해서 정한 것 (그리고 그 이유)

지시하신 대로 중간에 여쭤보지 않고 아래처럼 정했습니다.

| 갈림길 | 정한 것 | 이유 |
|---|---|---|
| 체크를 끄면 시각을 **지울까 / 남길까** | **남깁니다** (`alarmOn` 만 꺼짐) | 껐다 켤 때마다 시각을 다시 적는 것이 번거롭습니다. 데이터가 조금 남아도 해가 없고, 알람 동작은 체크(`alarmOn`) 하나로만 결정되므로 헷갈릴 일이 없습니다 |
| 알람을 **어디에 저장할까** | 메모 기록 안에 `alarmOn`·`alarmAt`·`alarmFiredAt` 세 항목으로 | 확인 체크·고정(`checked`·`pinned`)과 **같은 방식**입니다. 메모를 지우면 알람도 같이 사라지고, `JSON 내보내기` 백업에도 저절로 따라옵니다 |
| **저장 뒤** 알람 체크를 유지할까 | **끕니다** | 알람은 그 메모 하나에 붙는 것입니다. 켜둔 채로 두면 다음 메모에 실수로 알람이 붙습니다 |
| 지난 시각을 고르면 **막을까** | **막지 않고 미리 알려만 줍니다** | "3시간 전 일을 지금 기록하면서 알람을 바로 받고 싶다" 같은 쓰임을 막을 이유가 없습니다. 대신 저장 전에 노란 글씨로 알려드립니다 |
| 알람 확인 주기 | **15초** | 1분이면 최대 1분 늦게 울릴 수 있고, 1초면 배터리를 계속 씁니다. 15초면 사람이 느끼기에 "제때"이고 배터리 부담도 거의 없습니다 |
| 앱이 꺼져 있는 동안 지난 알람 | **다시 열 때 `지난 알람` 으로 알려줍니다** | 그냥 없던 일로 넘기면 알람을 맞춘 의미가 없습니다. 다만 늦었다는 사실은 분명히 알려드립니다 |
| 이미 울린 알람 | **다시 울리지 않습니다** (`alarmFiredAt` 표시) | 앱을 열 때마다 옛 알람이 계속 뜨면 못 씁니다. 다시 알림을 받고 싶으면 상세에서 **시각만 바꿔 저장**하면 됩니다 |
| 히스토리 목록에 **알람 표시(배지)** 를 넣을까 | **넣지 않았습니다** | "히스토리 화면의 체크/핀 등 다른 부분은 절대 수정하지 말 것" 이라는 지시에 따랐습니다. 필요하시면 다음에 배지만 따로 넣어드리겠습니다 |
| 백그라운드 알림 | **넣지 않았습니다** | 알림 권한 + 푸시 서버가 필요합니다 (위 2-4 참고) |

## 5. 그대로 둔 것 (건드리지 않은 부분)

원본에서 **지운 줄은 2줄뿐이고, 그마저도 뒤에 쉼표(`,`)를 붙이려고 다시 쓴 것**입니다.

## 9. 확인한 것 / 확인하지 못한 것

### ✅ 자동 검사로 확인한 것 (jsdom + 크롬 headless, **91건 전부 통과**)

**알람 설정 (입력 화면)**
- 처음에는 체크 꺼짐 · 날짜/시간칸 숨김 · 안내문 없음
- 체크하면 칸이 나타나고 **지금부터 1시간 뒤**가 자동으로 채워짐
- 지난 시각을 고르면 **⚠️ 경고 문구 + 노란 강조**
- 체크를 꺼도 **적어 둔 시각이 남고**, 다시 켜면 그대로 나옴
- 임시저장(초안)에 알람이 함께 담기고 앱을 다시 열면 되살아남
- 저장 뒤 알람 체크가 꺼진 상태로 되돌아감

**저장 · 데이터**
- 저장된 기록에 `alarmOn` · `alarmAt` · `alarmFiredAt` 이 정확히 들어감
- 알람을 안 켜도 저장이 정상 동작 (`alarmOn:false`)
- 기존 항목(`checked` · `pinned` · `sentTo` · `files` …)이 전부 그대로 유지됨
- 알람이 기록 안에 들어 있어 **JSON 백업에 자동 포함**

**알람 울리기**
- 시각이 지난 알람만 뜨고, 아직 안 된 알람 · 꺼둔 알람 · 이미 울린 알람은 뜨지 않음
- **알람 항목이 아예 없던 옛 기록에서도 오류 없음**
- 한 번 울리면 `alarmFiredAt` 이 남아 **다시 울리지 않음**
- 여러 개면 **이른 시각부터 하나씩**, `남은 알람: N개` 표시, 닫으면 다음 알람
- 앱이 꺼져 있는 동안 지난 알람은 **`⏰ 지난 알람`** 으로 표시
- `확인` 버튼 · 팝업 바깥 탭 · Esc 로 닫힘
- **`발송 중…` 팝업이 떠 있으면 알람이 기다렸다가**, 닫힌 뒤에 뜸

**상세(수정) 화면**
- 저장된 알람이 체크·시각까지 그대로 나옴 / 알람 없던 옛 기록은 꺼진 상태로 나옴
- `수정 저장` 으로 알람 켜기·끄기·시각 변경이 반영됨
- 알람을 꺼도 시각은 남고, **시각을 바꾸면 다시 울림**

**화면 (크롬 headless, 폰 크기 360×740)**
- 가로 넘침 **없음** (입력 화면 · 상세 화면 · 알람 팝업 모두)
- 알람 체크줄 44px · 날짜/시간칸 44px · 팝업 `확인` 버튼 54px
- 알람을 켜도 본문칸이 최소 90px 확보되고 화면이 깨지지 않음

**기존 기능 회귀 검사**
- 히스토리 확인 체크박스 · 📌 고정 표시 그대로
- 전송 버튼 4개 · 분류별 활성화 규칙(개인용→나에게만, 회사용→4개) 그대로
- 자동 제목(본문 첫 줄 / 첨부파일 이름) 그대로
- 첨부·손글씨·직접입력 팝업(칸 5개)·발송 결과 팝업·설정 화면 그대로

### ⚠️ 확인하지 못한 것 / 이번에 넣지 않은 것

- **앱이 꺼져 있을 때 울리는 알림 — 넣지 않았습니다.**
  브라우저 **알림 권한**을 따로 받아야 하고, 시각에 맞춰 폰을 깨워 줄 **푸시 서버**가 있어야 합니다.
  이 앱은 서버 없이 파일만 올려 쓰는 구조라 푸시 서버가 없습니다.
  "추가 설정(권한 등)이 필요하면 반영하지 말라"는 지시에 따라 넣지 않았고, 여기에 남깁니다.

## 3. 반영 내역 ② 리스트 최상단으로 이동(고정)

| 항목 | 내용 |
|---|---|
| 위치 | 히스토리 각 칸의 **맨 오른쪽 📌 버튼** |
| 노출 조건 | **'전체' 필터일 때만** 버튼이 보입니다. 개인용·집안용·회사용에서는 버튼이 사라지고, **고정 상태 자체는 그대로 유지**됩니다 |
| 동작 | 누르면 고정 / 다시 누르면 해제 (같은 버튼) |
| 정렬 | 고정한 기록은 목록 맨 위 `📌 고정한 기록 N개` 묶음에 모이고, **나중에 고정한 것이 위**에 옵니다. 고정하지 않은 기록은 예전처럼 날짜순 |
| 해제하면 | 원래 **날짜순 자리로 되돌아갑니다** |
| 최대 개수 | **5개**. 6개째를 고정하려 하면 고정하지 않고 팝업으로 안내합니다 → "고정은 최대 5개까지 가능합니다. / 기존 고정 항목을 해제한 후 추가해 주세요." |
| 표시 | 고정된 칸은 **테두리가 노란색**으로 바뀌고 `📌 고정` 배지가 붙습니다 (필터를 바꿔도 배지는 보입니다) |
| 저장 | 기록과 같은 저장소에 `pinned`, `pinnedAt` 으로 저장 → 앱을 껐다 켜도 유지 |
| 터치 영역 | 46 × 46 px |

### 찌꺼기 정리

기록을 지우면 그 기록의 확인·고정 표시도 **함께** 사라집니다.
(표시를 따로 저장하지 않고 기록 안에 같이 넣었기 때문입니다.)
그 위에 `tidyRecordFlags()` 정리 함수를 두어, 히스토리를 열 때마다 아래를 자동으로 손봅니다.

1. `checked` · `pinned` 항목이 없던 옛 기록에 기본값(꺼짐)을 채웁니다
2. 고정이 아닌데 남아 있는 `pinnedAt`(고정 시각) 을 지웁니다
3. 어떤 이유로든 고정이 6개 이상이 되면 **오래된 것부터 풀어 5개로 맞춥니다**
4. `JSON 가져오기` 로 백업을 합칠 때도 같은 정리를 거칩니다

## 4. 반영 내역 ③ ✍️ 직접입력 전송 대상

전송 버튼이 **3개 → 4개**가 되었습니다. 맨 오른쪽이 새로 생긴 `✍️ 직접입력` 입니다.
입력 화면 아래쪽과 **히스토리 상세 화면**(다시 이메일 전송) 두 곳 모두에 들어갔습니다.

| 항목 | 내용 |
|---|---|
| 위치 | `나에게` · `팀장들에게` · `팀장들+영업` **오른쪽(마지막)** |
| 활성화 | **분류와 무관하게 언제나 활성**입니다. 개인용·집안용에서도 눌립니다 |
| 기존 3개 | **규칙 그대로** — 개인용·집안용은 `나에게` 만, 회사용은 3개 모두 |
| 최대 인원 | **5명** (입력칸 자체가 5개라 그 이상은 적을 수 없습니다) |
| 주소 검사 | `a@b.c` 모양이 아니면 그 칸이 **빨갛게** 되고 보내지 않습니다 |
| 중복 | 같은 주소를 두 번 적으면 **하나로 합쳐서** 보냅니다 |
| 빈 칸 | 그냥 두면 됩니다. 다만 **한 개도 안 적으면** 보내지 않고 안내합니다 |
| 기억하기 | `이 기기에 기억하기` 를 켜 두면 다음에 팝업을 열 때 **주소가 미리 채워집니다** (이 기기 안에만 저장) |
| 지우기 | `모두 지우기` 를 누르면 칸과 기억해 둔 주소를 함께 지웁니다 |
| 전송 이력 | 히스토리에 `✓ 직접입력` 으로 남습니다 |
| 잠금 상태 | 개인정보 잠금이 걸려 있어도 **직접입력은 보낼 수 있습니다** (주소를 직접 적었으므로) |

### 화면 흐름

```
[✍️ 직접입력] 누름
        ↓
┌──────────────────────────────────┐
│ ✍️ 받는 사람 직접 입력            │
│ [개인용] 내일 회의 자료 … — 저장한 뒤 아래 주소로 보냅니다 │
│  1 [ hong@example.com          ] │
│  2 [ kim@example.com           ] │
│  3 [ (비워 두어도 됩니다)      ] │
│  4 [ (비워 두어도 됩니다)      ] │
│  5 [ (비워 두어도 됩니다)      ] │
│  최대 5명까지 보낼 수 있습니다.  │
│  [✓] 이 기기에 기억하기          │
│  [취소] [모두 지우기] [전송]     │
└──────────────────────────────────┘
        ↓
저장 → 발송 → 결과 팝업(기존과 동일)
```

> **주의**
> `저장 및 전송` 큰 버튼(확인 팝업)은 **건드리지 않았습니다.** 거기에는 예전처럼
> 분류에 맞는 그룹만 나옵니다. 직접입력은 **아래 버튼 줄에서만** 씁니다.

## 2. 오늘 반영한 내용

### 무엇이 문제였나

`저장 및 전송` 을 누르면 결과가 화면 아래에 **작은 글씨로 2.2초만 나타났다 사라졌습니다**(토스트).
손가락을 떼고 화면을 보는 사이에 이미 사라져서, **보내진 건지 아닌지 알 수 없었습니다.**

### 어떻게 바뀌었나

결과를 **화면 한가운데 팝업** 으로 띄우고, **[확인] 을 눌러야 닫히게** 했습니다.
저절로 사라지지 않으므로 결과를 놓칠 수 없습니다.

```
┌────────────────────────────────┐
│                                │
│              ✅                │  ← 큰 아이콘 (한눈에 성공/실패)
│          발송 완료             │  ← 성공은 초록 · 실패는 빨강 · 주의는 노랑
│  ‘나에게’ 에게 메일을 보냈습니다. │
│  ┌──────────────────────────┐  │
│  │ 받는 사람: aaa@bbb.com   │  │  ← 누구에게 · 무엇이 갔는지
│  │ 첨부: 첨부파일 2개        │  │
│  │ 메일에 붙은 파일: 2개     │  │
│  └──────────────────────────┘  │
│  ┌──────────────────────────┐  │
│  │           확인            │  │  ← 이걸 눌러야 닫힙니다
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

### ① 보내는 동안에도 상태가 보입니다

전송을 누르면 먼저 **`📤 발송 중…`** 팝업이 뜹니다.

- 아이콘이 천천히 깜빡여서 **작동 중** 이라는 걸 알 수 있습니다
- 이때는 **[확인] 버튼이 없고, 바깥을 눌러도 Esc를 눌러도 닫히지 않습니다**
  (결과가 나오기 전에 실수로 닫고 "보내진 건가?" 하는 일을 막기 위해서입니다)
- 응답이 오면 **같은 팝업이 그대로 결과 화면으로 바뀝니다**

### ② 성공했을 때 — 실제로 몇 개가 붙었는지까지 알려줍니다

어제 겪으신 **"보냈다는데 첨부가 빠져 있던 문제"** 를 앱이 스스로 잡아냅니다.

| 상황 | 팝업 |
|---|---|
| 첨부까지 정상 | ✅ **발송 완료** — `메일에 붙은 파일: 2개` |
| 첨부를 보냈는데 서버는 0개라고 답함 | ⚠️ **보냈지만 첨부가 빠졌습니다** + `⚠️ 파일이 붙지 않았습니다 — 앱스 스크립트를 '새 버전'으로 다시 배포해 주세요.` |

> 구글 앱스 스크립트가 알려주는 **실제 첨부 개수**(`attachments`)를 앱이 보낸 개수와 비교합니다.
> 옛 GAS처럼 개수를 아예 안 알려주면 비교하지 않고 그냥 `발송 완료` 로 표시합니다.

### ③ 실패했을 때 — 왜 실패했고 지금 뭘 해야 하는지

| 상황 | 팝업 | 안내 문구 |
|---|---|---|
| 인터넷·GAS 오류 | 📮 **자동 발송 실패 — 메일앱을 열었습니다** | 실패 이유 + `⚠️ 아직 보내지지 않았습니다. 메일앱에서 [보내기]를 눌러주세요.` |
| 메일앱(mailto) 방식 | 📮 **메일앱을 열었습니다** | 위와 같음 (메일앱은 사용자가 직접 보내기를 눌러야 나갑니다) |
| 받는 사람이 없음 | ⚠️ **보내지 못했습니다** | `설정 화면에서 받는 사람 이메일을 넣어주세요` |
| 개인정보가 잠겨 있음 | 🔒 **보내지 못했습니다** | [확인]을 누르면 **잠금 해제 창이 바로 열립니다** |
| 저장 공간 부족 | ⚠️ **저장하지 못했습니다** | `쓰신 내용은 그대로 남아 있습니다` |
| 내용이 비어 있음 | 📝 **저장할 내용이 없습니다** | [확인]을 누르면 본문칸에 커서가 갑니다 |

> **실패해도 메모는 이미 저장되어 있습니다.** 팝업에도 그렇게 적어 두었습니다.
> 히스토리 → 그 기록 → `다시 이메일 전송` 으로 다시 보내면 됩니다.

### ④ 그 외

- `저장만` 도 팝업으로 알려줍니다 (`✅ 저장했습니다` + 첨부 개수)
- 상세 화면의 `다시 이메일 전송` 도 **같은 팝업** 을 씁니다
- 팝업이 떠 있는 동안에는 **본문칸에 커서가 가지 않습니다**
  → 폰에서 키보드가 올라와 [확인] 버튼을 가리는 일을 막았습니다
- PC에서는 **Enter** 로도 [확인]이 눌립니다 (버튼에 미리 초점이 가 있습니다)
- **다른 UI는 하나도 건드리지 않았습니다.** 새로 넣은 CSS는 `.sheet.result` `.reslines` `.resline`
  세 종류뿐이고, 기존 팝업 틀(`.modal` `.sheet` `.modalbtns` `.btn`)을 그대로 재사용했습니다.
  색도 기존 변수(`--ok` `--danger` `--accent` `--card` `--line` `--sub`)만 씁니다.

## 7. 갱신 방법 (다음부터)

### 평소 갱신 절차

```powershell
cd C:\why2korea\claude\smartphone

```

### 버전 파일 관리 방식 (이 프로젝트 규칙)

- 원본(`index.html`)은 **직접 고치지 않습니다.**
- 고칠 때마다 `파일명.날짜.v번호.확장자` 로 **새 파일** 을 만듭니다
  → `index.20260804.v1.html`, 같은 날 두 번째면 `index.20260804.v2.html`
- 작업 전에 **먼저 폴더를 확인** 해서 같은 날짜 파일이 있는지 봅니다

  ```powershell
  Get-ChildItem C:\why2korea\claude\smartphone -Filter "*20260804*" -Recurse
  ```

- 배포할 때만 **복사해서 `index.html` 을 덮어씁니다**
- 작업 기록은 `README.날짜.md` 로 남깁니다 (같은 날 두 번째면 `README.20260804.v2.md`)

### 되돌리는 방법

```powershell
# 어제 것으로 되돌리기 — 보관본을 다시 복사하면 끝입니다

Copy-Item sw.20260803.v1.js      sw.js      -Force

git commit -m "index.html 되돌리기"
git push
```

### ⚠️ 앱 코드를 고칠 때마다 반드시 — `sw.js` 버전 올리기

```js
const CACHE_NAME = 'why2korea-memo-v6';   // 다음에 고치면 v7, 그다음 v8 …
```

빠뜨리면 **휴대폰이 옛 화면을 계속 보여줍니다.**

### GAS(직접 발송) — 아직 재배포 안 하셨다면

오늘은 GAS 코드를 고치지 않았습니다. 하지만 **어제 만든 첨부파일 지원 코드를

`⚠️ 보냈지만 첨부가 빠졌습니다` 라고 알려줄 것입니다 — 그게 정상 동작입니다)

> ★ **3번이 핵심입니다.** 저장(Ctrl+S)만 하면 `/exec` 주소는 **계속 옛 버전을 실행합니다.**
